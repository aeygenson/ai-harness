# Дизайн AI Harness (черновик для обсуждения)

Статус: **черновик**. Каждый раздел обсуждаем с Лизой; решения записываем в раздел
«Принятые решения» в конце. Код пишем только после согласования дизайна.

Связанный документ: [формат передачи работы (handoff)](handoff-format.md).

---

## 1. Цель и границы

**Что это.** Программа на Rust, которая ведёт задачу через четыре AI-роли:
Architect → (утверждение Лизы) → Developer → Tester → Security. Роли могут возвращать
работу назад. Провайдеры: Claude, OpenAI, Gemini, DeepSeek. Каждая роль оставляет короткие заметки (`notes.md`) и `handoff.json`.

**Для чего.** Учебный проект: понять, как устроены агентные системы, и получить
рабочий инструмент для будущей разработки.

**Что НЕ делаем в первой версии:**
- параллельную работу нескольких задач одновременно;
- работу через интернет/сервер (всё локально на компьютере Лизы);
- GUI (он будет позже, поверх того же ядра).

## 2. Общая архитектура

```
             ┌──────────────┐     ┌──────────────┐
  Лиза ────▶ │ harness-cli  │     │ harness-gui  │  (позже)
             └──────┬───────┘     └──────┬───────┘
                    └─────────┬──────────┘
                              ▼
                     ┌─────────────────┐
                     │  harness-core   │  оркестратор, роли, навыки,
                     │                 │  handoff, маршруты, хранение
                     └───┬─────────┬───┘
                         ▼         ▼
              ┌──────────────┐  ┌──────────────┐
              │  providers   │  │    tools     │
              │ Claude/OpenAI│  │ файлы, cargo │
              │Gemini/DeepSeek│ │  (песочница) │
              └──────────────┘  └──────────────┘
```

Rust workspace из нескольких crate (пакетов):

| Crate | Что внутри |
|-------|-----------|
| `harness-core` | типы handoff, конечный автомат (state machine), роли, навыки, хранение состояния |
| `harness-providers` | клиенты к Claude, OpenAI, Gemini, DeepSeek за общим интерфейсом |
| `harness-tools` | инструменты, которыми AI действует: читать/писать файлы, запускать тесты |
| `harness-cli` | команды для терминала |
| `harness-gui` | позже, скорее всего Tauri |

Почему так: ядро не знает, кто им управляет (терминал или GUI) и какой AI отвечает.
Это позволяет добавить GUI или нового провайдера, не переписывая логику.

## 3. Как работает одна роль (агентный цикл)

Это самый важный раздел: как AI на самом деле «пишет код».

**Вариант A — один запрос.** Отправляем промпт, AI отвечает текстом, в котором
содержимое файлов и handoff. Харнесс разбирает ответ и сохраняет файлы.
Просто, но AI не видит результат своих действий (например, не может запустить тесты).

**Вариант B — инструменты (tool use). ✅ Выбран.** Харнесс даёт AI набор
инструментов, и идёт цикл:

```
1. Харнесс → AI: промпт роли + навыки + задача + список инструментов
2. AI → Харнесс: «вызови read_file("src/lib.rs")»
3. Харнесс выполняет, возвращает результат AI
4. ... повторяется, пока AI не вызовет finish(handoff)
```

Инструменты (разные роли получают разный набор):

| Инструмент | Architect | Developer | Tester | Security |
|------------|:-:|:-:|:-:|:-:|
| `list_files`, `read_file`, `load_skill` | ✓ | ✓ | ✓ | ✓ |
| `write_file` | только `docs/` | ✓ | только `tests/` | — |
| `run_command` (`cargo build/test/clippy`) | — | ✓ | ✓ | ✓ |
| `finish` (сдать handoff) | ✓ | ✓ | ✓ | ✓ |

Ограничения внутри одной роли: максимум шагов (например, 50) и максимум токенов,
чтобы AI не зациклился и не потратил много денег.

Так работают Claude Code, Cursor и другие агенты — хорошая возможность понять это изнутри.

## 4. Роли и навыки (skills)

Каждая роль — папка с файлами, а не код. Её можно менять без перекомпиляции.

```
roles/
  developer/
    role.toml        # провайдер, модель, инструменты, лимиты
    prompt.md        # короткий базовый промпт роли
    skills/
      rust-error-handling.md
      write-idiomatic-rust.md
```

Пример `role.toml` (провайдера здесь нет: он задаётся в настройках проекта, см. раздел 8):

```toml
tools = ["list_files", "read_file", "write_file", "run_command", "finish"]
always_skills = ["write-idiomatic-rust"]
max_steps = 50
```

**Как выбираются навыки. ✅ Выбрано: AI сам просит навык.**

- В промпт роли попадает только **каталог**: название и одна строка описания каждого навыка.
- Полный текст навыка AI получает, вызвав инструмент `load_skill("rust-error-handling")`.
- Навыки из `always_skills` загружаются сразу, без запроса.
- Какие навыки роль загрузила, записывается в `skills_used` в handoff.

Так промпт остаётся маленьким, а AI берёт только то, что нужно для задачи.

## 5. Оркестратор (конечный автомат)

Оркестратор — это цикл, который знает текущее состояние задачи и решает, кто работает дальше.

```
          ┌───────────┐
  start ─▶│ Architect │◀───────────────────────────────┐
          └─────┬─────┘                                │
                ▼                                      │
          ┌───────────┐  вернуть                       │
          │   Лиза    │──────────▶ Architect           │
          └─────┬─────┘                                │
         утвердить                                     │
                ▼                                      │
          ┌───────────┐   дизайн неясен                │
     ┌───▶│ Developer │────────────────────────────────┤
     │    └─────┬─────┘                                │
     │          ▼                                      │
     │    ┌───────────┐   большая проблема             │
     ├────│  Tester   │────────────────────────────────┤
     │баг └─────┬─────┘                                │
     │          ▼                                      │
     │    ┌───────────┐   проблема в дизайне           │
     └────│ Security  │────────────────────────────────┘
          └─────┬─────┘
                ▼
              done
```

Правила — в [handoff-format.md](handoff-format.md#правила-маршрутизации): таблица
разрешённых переходов, предел 5 кругов, `needs_human` останавливает работу.

**Когда растёт `round`:** при каждом возврате назад (rejected). Предлагаю так.

**Сохранение состояния.** После каждого шага оркестратор пишет `state.json`.
Если программа упала или Лиза её закрыла, `harness run` продолжит с того же места.

## 6. Провайдеры (Claude, OpenAI, Gemini, DeepSeek)

Лиза планирует работать в основном **на подписках** (это дешевле), а не платить за
каждый запрос к API. Это важно, потому что подписка и API — разные вещи:

- **API** — платишь за токены, получаешь ключ, наша программа сама шлёт запросы.
- **Подписка** (Claude Pro/Max, ChatGPT Plus/Pro, Gemini) — ключа API нет. Легальный
  способ использовать её из программы — официальные консольные агенты:
  Claude Code (`claude -p`), OpenAI Codex CLI, Gemini CLI. Мы запускаем их как
  внешнюю программу в папке проекта и читаем результат.

Поэтому у нас **два вида бэкендов** за одним интерфейсом:

```rust
trait RoleRunner {
    /// Выполнить одну роль в папке проекта и вернуть handoff.
    async fn run(&self, job: RoleJob) -> Result<RoleOutcome>;
}
```

| Бэкенд | Как работает | Агентный цикл |
|--------|--------------|---------------|
| `api:*` — Claude, OpenAI, Gemini, DeepSeek через API | наша программа шлёт HTTP-запросы | **наш** (раздел 3): наши инструменты, наша песочница |
| `cli:*` — Claude Code, Codex CLI, Gemini CLI по подписке | запускаем консольного агента с промптом роли | **его собственный**: у агента свои инструменты; мы ограничиваем его настройками и проверяем результат |
| `mock` | заранее записанные ответы | для тестов, без денег и интернета |

Для API-бэкенда внутри есть общий клиент чата:

```rust
trait LlmClient {
    async fn chat(&self, request: ChatRequest) -> Result<ChatResponse>;
}
```

| Провайдер | API | Заметка |
|-----------|-----|---------|
| Claude | Anthropic Messages API | свой формат сообщений и tool use |
| OpenAI | OpenAI API | формат OpenAI |
| Gemini | Google Gemini API | свой формат; есть и OpenAI-совместимый режим |
| DeepSeek | совместим с OpenAI | тот же код, что OpenAI, другой адрес и ключ; очень дешёвый — хорош для учёбы |

И CLI-бэкенд, и API-бэкенд обязаны в конце дать `handoff.json` нашего формата.
Если агент его не написал или написал неправильно — роль считается упавшей, и харнесс спрашивает Лизу.

Библиотеки: `reqwest` (HTTP), `tokio` (асинхронность и запуск процессов), `serde` (JSON).

**Mock-провайдер** делаем первым ✅: проверяем весь цикл без денег и интернета.

-----------|-----|---------|
| Claude | Anthropic Messages API | свой формат сообщений и tool use |
| OpenAI | Chat Completions API | формат OpenAI |
| DeepSeek | совместим с OpenAI | тот же код, что OpenAI, другой адрес и ключ |

Каждый клиент переводит наш общий формат в формат своего API и обратно.
Библиотеки: `reqwest` (HTTP), `tokio` (асинхронность), `serde` (JSON).

**Фальшивый провайдер (mock)** для тестов: отвечает заранее записанными ответами.
Позволяет проверить весь цикл без денег и без интернета. Предлагаю сделать его первым.

## 7. Рабочее пространство и хранение

Проект, над которым работают роли, — **отдельная папка** от самого харнесса ✅.

```
my-project/                 # проект, который строят роли (свой git-репозиторий)
  src/ tests/ docs/ ...
  .harness/
    harness.toml            # настройки харнесса для этого проекта
    roles/                  # роли и навыки (раздел 4)
    runs/
      task-001/
        task.md             # описание задачи от Лизы
        state.json          # текущее состояние автомата
        round-01/
          architect/  notes.md  handoff.json  transcript.jsonl
          human/      notes.md  handoff.json
          developer/  ...
```

`transcript.jsonl` — полная запись разговора роли с AI (запросы, ответы, вызовы
инструментов). Для обучения и отладки это очень полезно.

**Git-коммит после каждой роли** ✅: харнесс сам делает коммит
«round 1: developer». Тогда в RustRover видно, что именно изменила каждая роль,
и можно откатиться.

## 8. Настройки проекта: какой провайдер у какой роли

Фиксированного назначения нет. **В начале каждого проекта** Лиза выбирает провайдера
и модель для каждой роли, и **может менять их в любой момент**. Это хранится в
`.harness/harness.toml` конкретного проекта:

```toml
max_rounds = 5

[roles.architect]
backend = "cli:claude"        # Claude Code по подписке
model = "<модель>"

[roles.developer]
backend = "cli:codex"         # Codex CLI по подписке ChatGPT

[roles.tester]
backend = "api:deepseek"      # дешёвый API, наш агентный цикл
model = "<модель>"

[roles.security]
backend = "cli:gemini"

[budget]
max_tokens_per_task = 2_000_000   # только для api-бэкендов
max_role_runs_per_task = 30       # для всех, включая подписки
```

- Изменение вступает в силу со **следующего запуска роли**; какой бэкенд работал,
  записывается в `transcript` каждого шага.
- Команда `harness config set roles.tester.backend api:claude` или правка файла вручную
  (позже — в GUI).
- **Ключи API — только в переменных окружения**: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`,
  `GEMINI_API_KEY`, `DEEPSEEK_API_KEY`. Никогда в файлах проекта, `handoff.json` или логах.
  Для подписок ключей нет: CLI-агенты используют свой вход (логин).
- **Бюджет**: для API считаем токены; для подписок токены не видны, поэтому ограничиваем
  число запусков ролей и останавливаемся, если агент сообщил о лимите подписки.

## 9. Интерфейс: сначала CLI, потом GUI

Команды CLI:

```
harness init                  # создать .harness/ в проекте
harness task new "описание"   # новая задача
harness run                   # вести задачу до следующей остановки
harness status                # где сейчас задача, сколько потрачено
harness approve [--note ...]  # утвердить дизайн (пишет handoff с role=human)
harness reject  --note ...    # вернуть архитектору
harness log                   # история ролей и вердиктов
```

GUI позже вызывает те же функции ядра: список задач, заметки ролей, diff кода,
кнопки «Утвердить» / «Вернуть».

## 10. Безопасность самого харнесса

AI выполняет действия на компьютере Лизы, поэтому:

- **Песочница по файлам**: все пути проверяются, выйти за папку проекта нельзя
  (`../../etc/passwd` будет отклонён). `.harness/` и `.git/` роли менять не могут.
- **Белый список команд**: только `cargo build`, `cargo test`, `cargo clippy`,
  `cargo fmt`. Никаких произвольных shell-команд.
- **Тайм-аут** на каждую команду.
- **Бюджет**: лимит токенов (API) и число запусков ролей (подписки); при превышении — стоп и вопрос Лизе.
- **CLI-агенты** запускаются только в папке проекта, с их собственными настройками разрешений
  в самом строгом режиме, который позволяет роли работать; после роли харнесс проверяет diff.
- **Ключи** не попадают в промпты и логи.

Позже можно запускать команды в Docker-контейнере для полной изоляции.

## 12. Открытые вопросы

1. Какие подписки у Лизы уже есть (Claude, ChatGPT, Gemini)? От этого зависит, какие CLI-бэкенды делать первыми.
2. Первый настоящий бэкенд (этап 5): `api:deepseek` (дёшево, и мы пишем агентный цикл сами — больше учимся)
   или `cli:claude` (по подписке, сразу полезно)? Рекомендую `api:deepseek` для учёбы, сразу за ним `cli:claude`.
